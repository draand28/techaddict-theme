# techaddict.ro incident and cleanup, 2026-11-21

WordPress at https://techaddict.ro/ was compromised. Malware had been present
since at least 2024 and was still deployed in October 2026. The phpBB forum was
not infected, but shared the same OS user and database account.

## What was found

Backdoors and webshells:

- `wp-includes/rss-tec.svg` - PHP shell disguised as an SVG, included on every
  WordPress request.
- `wp-config.php` - obfuscated loader appended after the table prefix.
- `index.php`, `wp-blog-header.php`, `wp-includes/class-wp-recovery-mode.php`,
  `wp-settings.php` - injected includes.
- Fake core files: `wp-xmltec.php`, `wp-intec.php`, `wp-xmlrpc.php`,
  `wp-customize.php`, `wp-content/.mdudql.php`.
- Disguised copies: `wp-includes/.lopbvy.php`, `wp-includes/.lwgztx.php`,
  `wp-includes/.tech`, `wp-includes/lqxuta.php`,
  `wp-includes/class-wp-rest-autosaves-controller-duotone.php`,
  `wp-includes/sodium_compat/src/Core32/Curve25519/Fe-calendar.php`,
  `wp-admin/.eojgsa.php`, `wp-admin/elyqpn.php`, `wp-admin/ms-dbaltr.php`,
  `wp-admin/options-fafjqn.php`.
- `wp-includes/css/dist/block-editor/.lwgztx.php`,
  `wp-includes/css/dist/block-editor/...` copy of the login page.
- `.well-known/about.php`, `.well-known/index.php` - shells.
- `wp-content/plugins/wp-piwik/libs/matomo-php-tracker/Seo.php` and
  `wp-content/plugins/wp-piwik/proxy/StorageCountry.php` - added files, not
  part of the plugin release.

Other findings:

- `.htaccess` set `DirectoryIndex wp-xmltec.php`, making the backdoor the
  default entry point.
- `wp-content/debug.log` had grown to 24 GB with PHP deprecation noise.
- WordPress core was 7.1.3 with 7.1.5 available; several plugins outdated.
- `users_can_register` was enabled with the `subscriber` default role.
- The WordPress database account `draand28` had full privileges on `*.*`
  (SUPER, FILE, CREATE USER) and was shared by every site on this server,
  the panel, and the Minecraft auth plugins.

## Actions taken

Backups first:

- `/root/backups/techaddict-malware-2026-11-21/html.tar` (full site, 24 GB)
- `techaddict_wp.sql.gz`, `techaddict_phpbb.sql.gz`
- `wp-config.after-clean.php`, Apache vhost backup in the same folder.

WordPress:

- Replaced `wp-admin/`, `wp-includes/` and all root PHP files with the clean
  7.1.3 release; updated core to 7.1.5.
- Removed every backdoor and fake file listed above; quarantined copies are in
  `/root/techaddict-cleanup/quarantine/` for inspection.
- Removed the injected loader from `wp-config.php`, restored `$table_prefix`,
  removed the duplicate `WP_DEBUG`, normalised line endings.
- Restored the stock WordPress `.htaccess` without the hijacked DirectoryIndex.
- Removed the 24 GB debug log; disabled `WP_DEBUG` and `WP_DEBUG_LOG`.
- Updated all plugins to current versions and verified checksums for every
  wordpress.org plugin.
- Removed the added wp-piwik files; plugin now verifies.
- Shuffled all WordPress salts (all sessions invalidated).
- Disabled open registration.
- Quarantined the unreferenced `smarthome/` sensor demo.

Database:

- Created `tcn_wp@192.168.45.133` (all on `techaddict_wp`) and
  `tcn_forum@192.168.45.133` (all on `techaddict_phpbb`).
- Switched both site configs to the new users; passwords are stored in the
  DPAPI secrets store as `TECHADDICT_WP_DB_PASSWORD` and
  `TECHADDICT_FORUM_DB_PASSWORD`.

Web server:

- `www.techaddict.ro` added as ServerAlias, 301 to the apex.
- HSTS, X-Content-Type-Options, X-Frame-Options and Referrer-Policy added to
  the TLS vhost.
- Apache config backed up before the change; `configtest` passed.

Cloudflare and DNS:

- `www` CNAME set to Proxied.
- SPF: `v=spf1 include:zoho.com ~all`.
- DMARC: `v=DMARC1; p=none; rua=mailto:admin@techaddict.ro; adkim=r; aspf=r`.
- Added `mx2.zoho.com` (20) and `mx3.zoho.com` (50).
- Added CAA for letsencrypt.org, pki.goog, digicert.com, sectigo.com.
- Minimum TLS set to 1.2; security level set to Medium.
- Cache purged.

## Verified

- `wp core verify-checksums`: passes.
- All wordpress.org plugins verify; no exact malicious filenames remain under
  `/var/www`.
- phpBB 3.3.19 core matches the official release; only `draand28` is in the
  administrator group; no request-driven `eval` shells.
- Apex and forum return 200; `https://www.techaddict.ro` returns 301 to the
  apex with a valid certificate.
- HSTS and the other headers are present on responses.
- SPF, DMARC, MX and CAA records resolve; TLS 1.2 works, 1.0/1.1 disabled.
- Secrets backup written to `G:\secrets` and `Y:\DevStuff\secrets`; restore
  tested into a temporary folder.

## Still open

1. The WordPress user table has 555,305 accounts; 555,141 registered from 2022
   onward are spam. Deleting them (keeping account IDs 1 and 2 and everything
   registered before 2022) still needs the owner's confirmation.
2. `wp-admin` and `wp-login.php` return 410 because of the earlier bot rule.
   Decide whether to allow them again, restrict by IP, or move the login path.
3. DNSSEC is enabled in Cloudflare but pending: no DS record at the .ro
   registrar. Add the DS or turn DNSSEC off.
4. DKIM is not configured for Zoho, and the SMTP password stored by WP Mail
   SMTP was readable through the database; rotate it in the Zoho panel.
5. `/var/www/techaddict_forum_ipb_backup` still contains a file matching a known
   shell hash. It is not served; delete or archive it after review.
6. `backup_GWH5id@%` has only USAGE; verify whether it is still needed and drop
   it if not.

## Credential rotation completed 2026-11-21

- `draand28` password rotated to a random value stored as
  `MYSQL_DRAAND28_PASSWORD`; all live configs on the web server and the
  Minecraft plugin configs were updated; global privileges revoked.
  It now has ALL only on: ade, reforme, nubis_site, tcn_authme,
  tcn_bungeeauth, tcn_forum, tcn_killstats, tcn_onlinetime, tcn_panel,
  tcn_phpbb3.
- `root@%` locked. Root now exists only on localhost, 192.168.45.133 and
  192.168.45.203; password stored as `MYSQL_ROOT_PASSWORD`.
- `wp-file-manager` deactivated and moved to
  `/root/techaddict-cleanup/quarantine/wp-file-manager`.
- Forum: `chg_passforce = 3650` days and `user_passchg = 0` for 16 active
  accounts, so each must set a new password at next login; all 779 sessions
  cleared.
